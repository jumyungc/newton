Automatic Rho Policy and Notation

rho is a row-local numerical ALM metric (often called the ALM penalty parameter). It is not the authored physical stiffness K. The two have the same units so that rho*C and K*C are generalized forces, but they have different jobs: K defines the intended material law, while rho determines the local row stiffness k_eff and the multiplier update rate.

For every finite material row, compliant ALM uses the same coefficient algebra:

s       = K / (K + rho)           multiplier scale
a       = rho / (K + rho)         material realization fraction
k_eff   = K*rho / (K + rho)       row stiffness placed in the local system
force   = k_eff*C + s*lambda
candidate_lambda = s*(lambda + rho*C)

K and rho therefore act like two stiffnesses in series. At a converged, unprojected finite-material fixed point, lambda = K*C and force = K*C: changing rho changes the path to the solution, not the authored compliance. For fixed rho, taking K large gives s -> 1 and k_eff -> rho, the hard-constraint ALM limit.

Coulomb tangentrho_t = max(A_t, min(rho_n, S_pair))Ideal Coulomb friction has no tangential material stiffness. The exact pair tangent block gives A_t = dt^-2/lambda_max(W0 + W1); min(rho_n, S_pair) adds structural support without exceeding the normal ALM metric. The candidate multiplier is projected onto ||lambda_t|| <= mu*force_n.

Each contact multiplier is updated once, so the projected candidate is applied directly:

lambda_next = candidate_lambda

A_n and A_t already include both endpoints' mobility. Endpoint count therefore does not rescale either rho or the multiplier update; this is the same rule for dynamic-static/kinematic and dynamic-dynamic contact.

SolverVBD contact history warm-starts numeric contact state but does not persist contact geometry. For compliant ALM, a matched row restores the normal multiplier. With latest matching, it also restores a tangential multiplier projected into the current tangent plane and Coulomb cone as a numeric warm start. With sticky matching, tangent history is carried by CollisionPipeline(contact_matching="sticky") through the replayed material anchor instead. The solver recomputes rho_n and rho_t from current geometry, timestep, mass, inertia, and structural support.

Numerical example. If K = 1000 and H = 100, then rho = 9000, s = 0.1, and k_eff = 900 (90% of K) in each local solve. A contact with K_n = 1000 and A_n = 100 instead uses rho_n = 100, s_n ~= 0.91, and k_eff,n ~= 90.9; accumulated lambda_n supplies the remainder as ALM iterations converge.

Takeaway

  • Both modes pass. In the 45-frame grid, history-free RMS error is 2.862 / 3.415 mm (legacy / ALM), with no stick/slide misclassifications.
  • The ideal static trajectory has zero downhill motion, so the table reports accumulated startup slip. Legacy is still tighter at four sweeps, but latest matching now gives the best four-sweep ALM static hold by restoring a projected tangential warm start on fresh geometry. Sticky remains the material-anchor mode and is useful where persistent contact geometry is required.
  • Net-force residual is the final contact-plus-gravity imbalance normalized by body weight. It must be read together with final speed: force balance alone can describe steady creep, while displacement alone cannot distinguish startup slip from a body that is still accelerating.
  • The retained formulation is finite normal compliance plus an unscaled ideal-Coulomb tangent. No stiffness conversion, cone heuristic, or predictor is used.
